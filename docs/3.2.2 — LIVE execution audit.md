Этап 3.2.2 — LIVE execution audit.

Цель: проверить текущий LIVE execution path после изменений pending_op. Ничего не менять в торговой стратегии, сигналах, entry logic, TWAP/PTB, risk settings или параметрах Bot B.

Нужно проверить код и тестами подтвердить следующие сценарии:

1. Успешный BUY:

- pending_op создаётся ДО place_market_order;

- AcceptedOrder корректно сохраняет order_id;

- trade_ids сохраняются только если реально возвращены;

- фактические fill price / size берутся из подтверждённого исполнения;

- position создаётся корректно;

- pending_op очищается только после однозначного результата.

2. RejectedOrder / FOK reject:

- позиция не создаётся;

- trade не создаётся;

- pending_op не остаётся зависшим;

- бот может продолжить работу.

3. Exception / timeout после вызова place_market_order:

- нельзя считать, что ордера не было;

- pending_op переводится в uncertain / needs_reconcile;

- новые BUY блокируются;

- SELL и flatten блокируются;

- restart не снимает блокировку.

4. Защита от дублей:

- второй BUY в том же market/window не должен отправляться;

- при активном pending_op повторный BUY не должен отправляться.

5. SELL / close:

- успешный SELL корректно уменьшает/закрывает position;

- rejected SELL не должен ложно закрывать position;

- exception при SELL должен оставлять состояние blocked/needs_reconcile;

- никакого ложного SETTLE.

6. Settlement:

- settlement не должен определяться только по balance;

- position/trade state должен обновляться только по доказуемому результату;

- проверить, что прежняя логика ложного SETTLE действительно устранена.

7. SDK:

- запускать тесты только через:

  D:\TEST\twap-hunter\.venv\Scripts\python.exe

- подтвердить polymarket-client==0.13.0

- системный C:\Python314\python.exe не использовать.

8. Тесты:

Добавить/обновить тесты только там, где нужно для проверки перечисленных сценариев.

В конце дать:

- список проверенных файлов;

- какие сценарии PASS/FAIL;

- точное количество тестов passed;

- найденные проблемы;

- были ли изменения в production-коде.

Ограничения:

- не реализовывать auto-reconciliation;

- не делать retry POST;

- не добавлять auto-resume;

- не менять Bot B strategy/settings;

- не менять paper execution;

- не трогать approvals;

- не менять entry_allowed;

- не менять TWAP/PTB;

- не менять order size;

- не делать реальных ордеров на Polymarket.
