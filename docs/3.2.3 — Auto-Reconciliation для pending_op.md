Этап 3.2.3 — Auto-Reconciliation для pending_op.

Цель:

научить real bot автоматически устанавливать фактический результат ранее отправленной операции после timeout/network exception/restart, не угадывая исполнение по balance.

Исходное состояние:

- polymarket-client==0.13.0

- pending_op уже сохраняется в SQLite до place_market_order

- состояния intent / posted / uncertain / needs_reconcile уже блокируют BUY/SELL/flatten

- блокировка переживает restart

- 3.2.2 LIVE execution audit полностью PASS

- retry POST и auto-resume пока отсутствуют

Нужно:

1. Исследовать доступные методы SDK/API для:

   - получения order по order_id;

   - получения fills/trades;

   - определения matched / live / cancelled / rejected / unknown состояния.

2. Реализовать reconciliation только для уже существующего pending_op.

3. Если есть order_id:

   - запросить его фактическое состояние;

   - восстановить fill size / fill price / trade ids;

   - корректно восстановить position/trade state;

   - очистить pending_op только если результат однозначно доказан.

4. Если order_id отсутствует:

   - не считать balance доказательством исполнения;

   - проверить, можно ли доказательно найти операцию через trades/fills/account history;

   - если однозначно идентифицировать операцию нельзя — оставить needs_reconcile.

5. Rejected / cancelled / definitively not-filled:

   - не создавать position/trade;

   - очистить pending_op только при доказанном terminal результате.

6. Partial fill:

   - восстановить только реально исполненный size;

   - не считать requested size исполненным.

7. Restart:

   - при старте real bot автоматически запускать reconciliation для pending_op;

   - до завершения reconciliation торговля остаётся заблокированной.

8. Не добавлять пока:

   - retry POST;

   - автоматическую повторную отправку ордера;

   - speculative balance inference;

   - изменения стратегии;

   - изменения TWAP/PTB;

   - изменения Bot B settings;

   - approvals.

9. Добавить isolated tests минимум для:

   - matched BUY after restart;

   - rejected order;

   - live/unresolved order;

   - partial fill;

   - unknown order;

   - pending_op без order_id;

   - reconciliation не создаёт duplicate BUY.

10. Все тесты запускать только через:

D:\TEST\twap-hunter\.venv\Scripts\python.exe

В конце дать отчёт:

- какие API/SDK методы использованы;

- какие файлы изменены;

- PASS/FAIL по каждому reconciliation case;

- количество тестов;

- в каких случаях pending_op очищается;

- в каких остаётся needs_reconcile;

- production-код изменения;

- что останется на следующий этап.

Не делать реальных ордеров.
