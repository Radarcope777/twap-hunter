Этап 3.2.5 — Auto-resume после успешной reconciliation.

Цель:

после доказанного terminal результата pending_op автоматически вернуть real bot в нормальную торговлю без ручного вмешательства.

Исходное состояние:

- 3.2.3 reconciliation работает;

- 3.2.4 классифицирует CONFIRMED_REJECT и UNKNOWN_SEND_RESULT;

- retry POST отсутствует;

- needs_reconcile блокирует BUY/SELL/flatten;

- pending_op очищается только при доказанном confirmed_fill или confirmed_empty.

Нужно:

1. После reconciliation:

- если confirmed_fill + amounts_ready:

  - корректно восстановить position/trade;

  - очистить pending_op;

  - снять needs_reconcile;

  - разрешить дальнейшую торговлю.

- если confirmed_empty:

  - не создавать position/trade;

  - очистить pending_op;

  - снять needs_reconcile;

  - разрешить дальнейшую торговлю.

2. Если состояние:

- live

- unresolved

- unknown

- ошибка API

- нет order_id/trade_ids

- fill без amounts_ready

то:

- needs_reconcile оставить;

- торговлю НЕ возобновлять.

3. Auto-resume не должен:

- делать повторный POST;

- повторно исполнять старый BUY;

- создавать duplicate position;

- снимать блокировку до завершения reconciliation.

4. Проверить restart:

- бот стартует;

- сначала reconcile pending_op;

- только после terminal reconciliation может перейти к обычному trading loop.

5. Добавить isolated tests:

- confirmed_fill → resume;

- confirmed_empty → resume;

- live → no resume;

- unknown → no resume;

- API error → no resume;

- restart + confirmed_fill → resume;

- restart + confirmed_empty → resume;

- no duplicate BUY immediately after reconciliation;

- no duplicate position/trade.

6. Не менять:

- стратегию;

- TWAP/PTB;

- Bot B settings;

- approvals;

- paper execution;

- retry logic.

7. Все тесты запускать только через:

D:\TEST\twap-hunter\.venv\Scripts\python.exe

В конце дать:

- какие файлы изменены;

- когда именно снимается needs_reconcile;

- когда блокировка сохраняется;

- количество passed/failed;

- production-код изменения;

- что останется на следующий этап.

Не отправлять реальные ордера.
